# Codex user-skill selection: separate main-based acceptance cell

**Local evidence for draft PR #1972, not release approval.** This extends the [project-skill ledger](component-insights-codex-main-skill-selection.md), not Codex skill-load measurement. All controls used disposable homes, an owner-only Registry draft, a loopback provider and the isolated main-based API/worker. Native prompts, transcripts, skill contents, credentials, private IDs and desktop/mobile captures are outside Git. No ordinary harness home, production instance or unrelated Docker project was changed.

## Boundary and implementation

Only Codex CLI **0.163.0** native inventory and its linked `skills.selected_skill_instructions` selection record are recognized. A rooted `~/.agents/skills/<alias>/SKILL.md` inventory entry is a *candidate*, not proof of the user's home or Registry identity: publication requires an exact location digest, one contemporaneous resolved/versioned **user-scope** pin, matching file bytes in the v2 layer and no same-name project, parent or other home placement. Duplicate native aliases, incomplete or noncanonical source, an invalid typed-turn link, mismatched selected path and unfamiliar versions are unsupported. A changed file is drifted; a same-name shadow is unverified. Neither can create a measured zero.

The CLI now scans the bounded native user skill manifest, verifies the user's installed file against its pull-time fingerprint and publishes its location digest/status alongside the layer. Without a native working directory the verifier cannot exclude a project shadow and withholds the user pin. The Codex extractor separates user and project evidence without treating a skill mention, pasted text or file read as a native selection. The shared publication version is **13398** (skill matcher 5). The SQL denominator for Codex now permits a uniquely verified **project-only or user-only** install **only with an attributed native offered fact for this listing in that session**. A supported native inventory for an unrelated user root cannot turn a verified but unoffered project skill into a measured no-selection result. Mixed installs, unverified offers, unsupported source and pending projection remain unknown. Presence, offer and selection are different facts. Confirmed loads and attempts remain **null / not recorded**, not zero.

## Project-offer denominator correction

A read-only audit found that a Codex inventory containing only an unrelated user skill could still have a complete skill publication and a verified **project** pin for this listing. The extractor correctly attributed no project offer, but the first user-scope SQL revision would have counted the project pin as a measured no-selection. The corrected project branch now also requires this listing's attributed native offer when the harness records availability. A structural native-root/pin regression and complete-but-unoffered project coverage regression guard the exclusion; the per-session reader returns null rather than a misleading zero.

The corrected bounded cross-slice suite ran read-only in the dedicated isolated API image with pytest mounted read-only: **461 passed**. Ruff, REUSE and the SQL fingerprint passed; the isolated API image built. OrbStack stopped on the first restart attempt, without deleting any volumes; a second start with an explicit Compose environment file restored only the isolated stack and its original four volumes. The running API reported the **corrected** query fingerprint at publication version **13398**. Read-only ClickHouse evaluation of the exact SQL scope expression returned measurable for a uniquely verified project/user pin **with an attributed offer**, and unmeasurable for a project/user pin without an offer, a mixed pin and no pin. A bounded forced replay of the **two fresh AGENTS.md project sessions, two user sessions and independent imitation** created new complete generations without changing their one-offer-per-session or selected/negative classifications. Scoped owner API and source-matched CLI `activity`/`sessions` agreed before and after replay: each two-session cohort had **2 verified-present / 2 measured / 2 offered / 1 selected**; the imitation had **1 / 1 / 1 / 0**. The post-replay CLI used a private interpreter with this checkout's source and matching local development-version metadata, not a published release artifact. Confirmed loads and attempts remained null. Fresh completed worker reports for both two-session cohorts, CLI `show`, sanitized HTML and loopback-only main-source desktop/mobile browsers retained those figures and the selection-not-load label. The corrected report/export check found no skill body, AGENTS.md instructions or credential. Earlier completed reports were not reused as corrected-head evidence.
